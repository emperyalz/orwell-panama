# Local Codex agent activity bridge

Run `node scripts/agent-activity-bridge.mjs --once` to inspect the sanitized dry-run snapshot. Run `node scripts/agent-activity-bridge.mjs --watch --publish` from this repository to send activity to the production `agentActivity:record` internal Convex mutation. Publishing uses the local Convex CLI credentials and records the latest activity plus the most recent model change and turn ending seen in the bounded tail. Polls and CLI writes run sequentially. The persistent state defaults to `~/.codex/orwell-agent-bridge-state.json`; `--state` and `--sessions` override the paths. The watch poll interval is 15 seconds.

The collector reads a bounded 8 MB tail of each log plus its first metadata line. It may omit older activity when an agent produces a larger log; the current view favors recent status. The collector reads only the root Codex session `01a09321-0212-73f0-b32b-c3045945d6c6` and session files whose `session_meta.source.subagent.thread_spawn.parent_thread_id` matches that ID. Other sessions are ignored even if they share the same workspace. It sends IDs, nickname or configured name, team, model, reasoning effort, status, timestamps, and fixed English, Spanish, Portuguese lifecycle labels. Tool names are reduced to broad fixed activity categories. It never sends prompts, message bodies, reasoning, tool arguments, command text, tool outputs, or raw event content. The event ID uses session ID, log filename and byte offset for Convex deduplication. The bounded tail and selected events provide a current-activity view rather than an exhaustive transcript. Known model and reasoning metadata persist in the local state file for tails that start after the last turn context.

Optional `scripts/agent-activity-config.json` keys may be an agent path such as `/root/social_identity_qa` or a session ID. Each value supports `name`, `team` (`research`, `qa`, `implementation`) and `assignment` with `en`, `es`, `pt` strings. Keep these labels generic and suitable for public display. Without config, the nickname and path determine the name and team; assignment is generic. This config is a local, explicit allowlist for public task descriptions, not a transcript parser.

The bridge runs only while this machine can read Codex logs and has network and Convex CLI access. A quiet or stopped bridge cannot prove an agent is working; the UI must mark old timestamps stale. A completed turn means that turn ended, not that the entire project task is complete. A publish failure is reported locally and retried on the next poll; the bridge does not invent a running status or hide the failure.

## Workstation availability

At Eric’s request, the user LaunchAgent `com.orwell.keep-awake` runs `/usr/bin/caffeinate -i -s`, with RunAtLoad and KeepAlive. System assertions were verified active. It prevents idle system sleep and sleep while on AC without asserting display wakefulness. Display timeout remains fifteen minutes; other apps may hold their own display assertions. It starts after user login. Leave the Mac connected to power with its lid open for unattended work. This does not override intentional shutdown, power loss or normal closed-lid sleep. Keep-awake is separate from the event collector and does not synthesize agent activity.

## Understandable failures

Every failure card must show a plain-language cause and its recovery status. Record the actual replacement agent when work transfers. Keep the original failed runtime status as history, display a recovered badge only after verified recovery, and clear that diagnosis if a later failure occurs. If the cause is unknown, say so explicitly. Never publish raw credentials, prompts or diagnostic payloads.
