# Bounded parallel workspace preparation

- [x] Real detached git worktrees retain stable position and item leases. At most two author/preparation lanes can be reserved; overlapping writable ownership, duplicate positions and unmet dependencies hold allocation.
- [x] Each worktree overlays the current root workspace source, including relevant untracked product files. It records a private exact source manifest; provider secrets, environment files, npm authentication config and browser/session directories are excluded.
- [x] Every lane's scoped mutation check compares its own before/after source manifests. A second lane cannot alter another lane's source by an ordinary edit in its own directory. The meaningful regression creates two real worktrees, attempts a cross-scope edit, checks the unchanged other lane and root source, and tests stale/same-lease snapshot refusal.
- [x] Preparation source snapshots are fresh root-owned read-only files/directories. Native Claude receives only Read/Grep/Glob tools. Separate Sonnet sessions inspect two actual original career-history backlog items; a fresh Opus session reviews the reports and reopens source. This produces preparation evidence, never product acceptance.
- [x] The preparation service holds the existing controller flock across the batch, so central product model execution/release cannot race this bounded batch. Two preparation calls run concurrently; QA starts only after both finish. Native quota is checked before every call and every45seconds with three additional usable points reserved for review. Original policy/baselines/reserves/expiry are read unchanged. Three projected native runs must fit existing global finite ceilings. All native receipts use the existing controller runs directory and count toward its global limits.
- [x] Identical private preparation jobs are idempotent. An existing matching batch, including a failed/interrupted batch, is retained without duplicate inference. A systemd timer can reconcile the same allowlisted jobs without a Mac. New tasks require root changes to the private jobs allowlist and must remain among the original planner-policy item keys.
- [x] Root private preparation inventory records source/snapshot revisions, report hashes, contributor/reviewer sessions and exact receipt paths. Reports can inform the normal planner. They are never automatically applied to source, published, deployed, or checked off.
- [ ] Concurrent mutable product authors are not enabled. Backend dispatch currently admits one product lease, affinity pins one item, and QA/release bind the exact whole-workspace revision. Full parallel authors require backend per-lane claims and roster bindings, shared native budget reservations, safe scoped integration onto the current accepted base, conflict/dependency checks, and fresh QA of the exact merged candidate before the single protected release. These gates remain intact.
- [ ] Thirty-two roster positions do not imply32concurrent runnable workers. This service currently allows exactly two configured preparation positions and one serial independent review position; arbitrary roster auto-dispatch is not enabled.
